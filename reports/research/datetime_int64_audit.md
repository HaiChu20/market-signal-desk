# Datetime-to-int64 resolution audit

Audit date: 2026-11-13. Pandas 3.1.1 preserves parquet timestamps as `datetime64[us, UTC]` unless code explicitly normalizes their unit. Dividing their raw integer representation as if it were nanoseconds is therefore unsafe.

| Site | Affected? | Finding | Affected artifacts |
|---|---|---|---|
| `processing/wide_v1.py::_event_jobs` | **Yes** | Bar integers were microseconds divided by 1e9, while deadlines were epoch seconds. The kernel never reached deadlines and unresolved trades exited at the end of the loaded window. Replaced with shared `epoch_seconds`. | `events_wide_v1`, invalid scratch `events_wide_hold3_v1`, accepted Family-1 wide-v1 results, and Test-v1 fixed event outcomes. New corrected artifacts must be versioned. |
| `research/benchmark.py::random_direction` | **Yes** | Same unsafe bar timestamp conversion. Opposite-direction simulations did not honor their declared deadline. | Tournament and Families 3–5 random-direction percentiles. Their model OOF predictions, returns, Brier scores, and CPCV results are not affected by this site. |
| `processing/labels.py::label_grid` and `labels_wide_v1` builder | No | Uses `timestamp_ints`, now backed by shared `epoch_ints`, with explicit ns normalization for bars and deadlines. A direct us/ns regression test covers it. | `labels_wide_v1` is valid. Family-2/Roihu v5 wide targets and Families 3–5 targets are not invalidated by the deadline-unit bug. |
| `processing/crypto_perp.py` grid builder | No | Calls safe `label_grid`; its funding helper explicitly requests `datetime64[ns]`. | Binance-perpetual grid labels remain valid. |
| `processing/pipeline.py::label_method_events` | No | Explicitly casts event-bar timestamps to `datetime64[ns, UTC]` before seconds. | Production native event labels and frozen detector replay are not affected by this conversion bug. |
| `processing/features.py` lines formerly near 323/530 | No in persisted production features; hardened | `external_feature_frame` normalizes incoming `known_at` to ns, and `prepare_feature_cache` normalizes `history.ts` to ns before constructing `out.known_at`. Raw casts were nevertheless replaced with `epoch_ns` to make the invariant local. | Persisted dense features and configured F3/F4/F5 feature values remain valid. |
| `research/family.py` | No datetime conversion | Its `astype(int64)` constructs numeric event keys from anchor indices. Label timestamps are normalized through `_utc`; wide labels use the safe grid kernel. | F3/F4/F5 core OOF metrics remain valid. Only their random benchmark diagnostic is affected as noted above. |
| `research/sequence_data.py`, `sequence_train.py` | No | Alignment uses timezone-aware `DatetimeIndex.searchsorted`, not raw epoch integers. | Sequence windows are unaffected by this unit issue. |
| `hpc/roihu/sequence/make_bundle.py` and v5 config | No | Inventory/coverage uses timestamps and `DatetimeIndex`; it does not convert datetime values to raw int64. It packages safe `labels_wide_v1`. | `bundle_dev_v5_wide` does not need rebuilding for this deadline bug and may be submitted. |
| `research/test_exam_v1.py` | **Yes, transitively** | The exam called `_event_jobs`, so its intended one-day time exits could extend to the loaded-window end. | Test-v1 did not implement the preregistered exit. Test is spent and will not be rerun; verdict remains FAIL with an addendum. |
| `data/histdata.py::detect_roll_records` | Potentially yes for us inputs; fixed | Raw `work.ts.astype(int64)` was compared with ns `Timestamp.value`. Replaced with `epoch_ns`. | HistData futures roll-detection diagnostics generated under us-resolution inputs may need regeneration; the five-core-market cash-era DEV event replay is not based on this roll detector. |
| backtest, dataset, levels, live engine, method level joins | No | Every datetime conversion explicitly casts to `datetime64[ns, UTC]`, or uses `Timestamp.value`/the shared helper. Day ordinals and numeric event-key casts are intentionally not epoch-nanosecond conversions. | No affected artifacts identified. |

The shared implementation is `msd.processing.timeutil.epoch_ints`, with `epoch_ns` and `epoch_seconds` convenience functions. Tests cover identical us/ns results and a Rust-kernel time exit at the declared deadline.
